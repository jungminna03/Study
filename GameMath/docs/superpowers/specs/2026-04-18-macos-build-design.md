# macOS Build Support — Design Spec

Date: 2026-04-18
Status: Approved

## Goal

Add a macOS build for the `GameMath` Siv3D app alongside the existing Windows
build, so the project compiles and runs on both platforms from a shared
`Main.cpp`. Windows build (`GameMath.slnx` / `GameMath.sln` on MSVC `v145`)
must continue to work unchanged in behavior.

## Constraints

- Siv3D 0.6.16 is Windows-only in its official binary; macOS distribution is
  `~/Siv3D/` (installed, env var `SIV3D_0_6_16_MACOS` set in `~/.zshrc`).
- Siv3D macOS is officially distributed as an Xcode project template
  (`examples/empty/empty.xcodeproj`) with non-trivial framework dependencies.
- Primary macOS IDE is Rider (JetBrains), which can open `.xcodeproj`
  but can also use it indirectly via Xcode CLI tooling.
- Single-source policy: one `Main.cpp` consumed by both platforms.

## Directory Structure

```
GameMath/
├── GameMath.slnx, GameMath.sln        # Windows (existing)
├── GameMath/
│   ├── GameMath.vcxproj               # Windows (existing, edited)
│   ├── Main.cpp                       # shared
│   └── App/                           # shared assets
└── GameMath-macOS/                    # new
    ├── project.yml                    # xcodegen source of truth
    ├── Info.plist
    └── icon.icns
```

`GameMath-macOS/GameMath.xcodeproj/` is generated by xcodegen and gitignored.

## Source Changes — PCH Removal

Current: `stdafx.h` is force-included via `<ForcedIncludeFiles>stdafx.h</ForcedIncludeFiles>`
in the vcxproj and `stdafx.cpp` generates the PCH. macOS Xcode build has no such mechanism.

Decision: remove the PCH on Windows rather than introduce a macOS-only prefix
header. Makes the code path identical on both platforms.

- Delete `GameMath/stdafx.h` and `GameMath/stdafx.cpp`.
- Add `# include <Siv3D.hpp>` as the first line of `GameMath/Main.cpp`.
- Edit `GameMath/GameMath.vcxproj`:
  - Remove `<ForcedIncludeFiles>stdafx.h;...</ForcedIncludeFiles>` from both Debug and Release
    `<ClCompile>` item-definition groups.
  - Remove `<PrecompiledHeader>Use</PrecompiledHeader>` from both.
  - Remove the `<ClCompile Include="stdafx.cpp">...Create...</ClCompile>` entry.
  - Remove `<ClInclude Include="stdafx.h" />`.

Tradeoff: each clean build re-parses `<Siv3D.hpp>` (heavy). The project has one
translation unit (`Main.cpp`), so impact is negligible.

## Siv3D SDK Reference

Symmetric to the existing Windows env var (`SIV3D_0_6_16`):

- `SIV3D_0_6_16_MACOS="$HOME/Siv3D"` (already appended to `~/.zshrc`)
- `~/Siv3D/` contains `include/`, `lib/`, `examples/`, `addon/` (moved from
  `~/Downloads/siv3d_v0.6.16_macOS/`)

Used by the Xcode project via `$(SIV3D_0_6_16_MACOS)` in:
- `HEADER_SEARCH_PATHS`
- `LIBRARY_SEARCH_PATHS`

## Xcode Project — xcodegen

Generator: [xcodegen](https://github.com/yonaskolb/XcodeGen), installed via Homebrew.
Rationale: keeps the project definition in a declarative `project.yml` that is
git-friendly, avoids hand-editing `.pbxproj`, and makes the generated
`.xcodeproj` a build artifact.

`GameMath-macOS/project.yml` (outline — exact linker flags and framework list to
be confirmed against `~/Siv3D/examples/empty/empty.xcodeproj` during
implementation):

```yaml
name: GameMath
options:
  bundleIdPrefix: com.nyxrux62
  createIntermediateGroups: true

settings:
  base:
    MACOSX_DEPLOYMENT_TARGET: "12.0"
    CLANG_CXX_LANGUAGE_STANDARD: "c++20"
    CLANG_CXX_LIBRARY: "libc++"
    HEADER_SEARCH_PATHS:
      - $(SIV3D_0_6_16_MACOS)/include
      - $(SIV3D_0_6_16_MACOS)/include/ThirdParty
    LIBRARY_SEARCH_PATHS:
      - $(SIV3D_0_6_16_MACOS)/lib

targets:
  GameMath:
    type: application
    platform: macOS
    sources:
      - path: ../GameMath/Main.cpp
    info:
      path: Info.plist
      properties:
        CFBundleName: GameMath
        CFBundleExecutable: GameMath
    settings:
      base:
        PRODUCT_NAME: GameMath
        OTHER_LDFLAGS: [ -lSiv3D, ... ]  # extracted from empty template
    dependencies:
      # Frameworks (OpenGL, Metal, MetalKit, CoreAudio, AudioToolbox,
      # AVFoundation, CoreMedia, CoreVideo, AppKit, IOKit, ...)
      # Final list copied from empty template during implementation.
    postBuildScripts:
      - name: Copy App Resources
        script: rsync -a --delete "$SRCROOT/../GameMath/App/" "$TARGET_BUILD_DIR/$PRODUCT_NAME.app/Contents/Resources/"
```

Generation:
```bash
cd GameMath-macOS && xcodegen generate
```

## App/ Resource Handling

Windows: `App/` is the debugger working directory; Siv3D reads assets with
relative paths.

macOS: assets must live inside `GameMath.app/Contents/Resources/`. Implemented
as a build phase that mirrors `../GameMath/App/` into the Resources dir of the
generated bundle on every build.

## Definition of Done

1. `cd GameMath-macOS && xcodegen generate` runs with no errors.
2. `xcodebuild -project GameMath-macOS/GameMath.xcodeproj -scheme GameMath -configuration Debug build` succeeds.
3. Launching the built `.app` shows the same centered grid + red/green axes +
   keyboard-controlled ball as the Windows build.
4. Opening `GameMath-macOS/GameMath.xcodeproj` in Rider: `Main.cpp` is editable,
   run action is active.
5. On Windows (user-verified), `msbuild GameMath.sln /p:Configuration=Debug
   /p:Platform=x64` still succeeds with PCH removed, and `GameMath/App/GameMath(debug).exe`
   is produced and runs as before.

## Out of Scope (YAGNI)

- Release-configuration tuning on macOS beyond mirroring Debug.
- CI / automated builds (study project, local-only for now).
- CMake alongside Xcode (option B from brainstorming — rejected).
- Siv3D version upgrade (pinned to 0.6.16).
- Cross-platform unit tests.

## Risks

- **Framework / linker flag list drift** — the exact list must be extracted
  from `~/Siv3D/examples/empty/empty.xcodeproj/project.pbxproj`. First
  implementation task.
- **Siv3D macOS runtime-only dependencies** — any assets the engine expects
  at bundle-relative paths (e.g., shaders under `engine/shader/glsl/`) must be
  present. `App/` already contains them, but the copy phase must preserve
  directory structure.
- **Windows regression from PCH removal** — user to verify on Windows after
  merge. Revert path is straightforward if broken.
